# Plume Media and Plume Travel for plumestudioscreatives.com

This folder is the code that puts the full Plume Media and Plume Travel designs on
plumestudioscreatives.com, the Lovable project `petal-connect-commerce`. Both open from the site's
existing left sidebar (`AppShell`, the "Explore" section), which is not changed.

- **Plume Media** (`/media`): Learn, Read and Watch, Studio, My Collection, classes, the player.
- **Plume Travel** (`/travel/...`): Discover, listings, itineraries, Passport, Rooms, Following, Host
  Studio with the Partnership board, My events, Results and Check-in, and Admin.

Everything is interactive and runs on sample data in the visitor's browser. Nothing reads or writes
Supabase or Stripe. Until Plume opens on October 30, buying a class, booking a place, joining an
event waitlist and claiming a place stop with "opens October 30" and a link to the site's waitlist.
No card details are ever asked for.

## How it fits the site

- **Sidebar.** Unchanged. Its links already go to `/media` and `/travel`, and "Plume Travel" stays
  highlighted on every `/travel/...` page.
- **Type.** The site's rule is Cormorant Garamond for everything (`plume-tokens.css`). Both sections
  follow it. Plume Media was drawn with a sans for body text, so on the site its body text is set 15%
  larger and at medium weight; headings keep their sizes. Plume Travel already used Cormorant.
- **Phones.** The site's bottom tab bar stays at the bottom. Plume Media's section tabs (Home, Learn,
  Read, Watch, Library) move under its header, and Travel's "Book" bar and messages sit above the tab
  bar.
- **Styles stay contained.** Every Media rule is scoped under `.plume-media` and every Travel token is
  prefixed `--tv-`, so neither changes any other page. Tailwind doesn't scan Plume Media
  (`@source not`), so its class names can't create stray utilities.
- **Server rendering.** The sidebar and each page's head still render on the server. The two designs
  render in the browser (`ClientOnly`), because they keep the preview's state in local storage and
  draw randomized illustration details.
- **Accounts.** None needed. Every visitor gets the sample-data preview with the "View as" switcher
  (Travel) and the demo switcher (Media).

## Getting it into Lovable

Lovable keeps this project in sync with the `main` branch of
`plumestudioscreatives-collab/petal-connect-commerce` on GitHub. 95 files is too many to paste into
Lovable's chat, so the reliable route is through GitHub:

1. The files land on a branch of `petal-connect-commerce` (copy `files/` and `changes/` over the
   project, or let Claude push the branch and open a pull request).
2. You review the pull request and merge it into `main` when you're ready.
3. Lovable picks up the change. Open the project, check `/media` and `/travel` in the preview, then
   give Lovable the prompt below.
4. You click Publish in Lovable when you're happy with it.

### Prompt for Lovable (after the merge)

> Plume Media (`/media`) and Plume Travel (`/travel/...`) were added through GitHub as complete,
> approved designs that run on sample data. Please don't rewrite, restyle or "simplify" anything in
> `src/features/media`, `src/features/travel`, `src/features/launch.ts` or the `/media` and
> `/travel*` routes, and keep the `AppShell` sidebar as it is.
>
> 1. Run the build and fix only real errors, if any, without changing how either section looks.
> 2. Check these pages in the preview at desktop and phone width: `/media`, `/media?view=course&id=c3`
>    (choose "Buy": it should say paid classes open October 30), `/travel`, `/travel/board`,
>    `/travel/studio/events`, and a listing such as `/travel/e/e4` (choose RSVP: it should say
>    booking opens October 30).
> 3. Confirm the sidebar highlights Plume Media on `/media` and Plume Travel on every `/travel/...`
>    page, and that the phone tab bar doesn't cover anything.
> 4. Don't connect Supabase, Stripe or any real data to these sections yet. That happens in separate
>    steps after October 30 planning, one feature at a time, with my approval.

## Decisions for you

1. **Who sees the preview.** Right now every visitor to `/media` and `/travel` gets the full
   sample-data preview. If you'd rather only some people see it before October 30, say so.
2. **Plume Media's type.** It follows the site's Cormorant-only rule. If you'd rather keep Media's
   original sans for body text, that's one line in `media.css`.
3. **Teaser pages.** `MediaPage.tsx` and `TravelPage.tsx` (with your photos) are no longer shown.
   Keep them for later, reuse their photos inside the designs, or delete them.
4. **After October 30.** Which comes first for real data: Travel booking (with Stripe Connect) or
   Media classes. Each is a separate step with its own preview and your approval.

## Rebuilding this folder

```bash
cd prototypes/plume-lovable
APP_DIR=/path/to/petal-connect-commerce node assemble.mjs   # refresh files/ and changes/
npm install && APP_DIR=/path/to/petal-connect-commerce npm run showcase   # the preview, in showcase/dist
```

The sources are `prototypes/plume-media` and `prototypes/plume-travel`; edit those, not `files/`.
The preview copies the site's sidebar, pages and photos in at build time and doesn't commit them,
because this repository is public.
